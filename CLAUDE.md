# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A kid-friendly educational quiz app for ages 5-9. React 19 + TypeScript + Vite 8 + Tailwind 3 + Zustand. Backend is pluggable: localStorage mock for dev (default), Supabase Postgres in production via env-routing.

Five modules: Math (procedural), Vehicles, Grammar, Animals, Science. Animals + Science are 7-9 only — their JSON pools have no 5-6 entries, and `MODULES_FOR_BAND` / `computeModuleProgress` filter them out for 5-6 profiles.

## Commands

```bash
npm run dev                  # vite dev server
npm run build                # tsc -b && vite build
npm run lint                 # eslint .
npm run test                 # vitest run

# Single test file:
npx vitest run src/path/to/file.test.ts --pool=threads

# Single test by name:
npx vitest run -t "name fragment" --pool=threads
```

**Vitest pool gotcha (this devcontainer):** worker startup is flaky on the default `forks` pool — running the full suite often hits `Timeout waiting for worker to respond` on ~half the files, even though individual files pass. Always use `--pool=threads`, and split large invocations:

```bash
npx vitest run src/services --pool=threads
npx vitest run src/features/quiz src/features/results --pool=threads
npx vitest run src/components src/lib src/stores --pool=threads
```

The "1 file failed / Errors" from `canvas-confetti` `clearRect on null` is a pre-existing jsdom limitation (no canvas backend); the underlying assertions all pass. Ignore unless you're touching results/confetti.

## TypeScript flags worth knowing

`tsconfig.app.json` enforces three flags that catch agents off-guard:
- `erasableSyntaxOnly` — no `enum`, no parameter properties (`constructor(public x: T)`), no `namespace`. Use `as const` objects + explicit field assignment.
- `verbatimModuleSyntax` — type-only imports must be `import type { Foo }` not `import { Foo }`.
- `noUnusedLocals` / `noUnusedParameters` — prefix with `_` to opt out.

## Backend architecture (the core "big picture")

Two backends share one interface; a selector chooses at module-load time:

```
src/services/
├── mockBackend.ts        — localStorage-backed; default fallback; source of truth for types
├── supabaseBackend.ts    — Supabase RPC + direct CRUD; mirrors mockBackend interface 1:1
└── backend.ts            — selector: returns supabase if VITE_SUPABASE_URL + VITE_SUPABASE_ANON_KEY set, else mock
```

**Critical**: `mockBackend.ts` owns the type definitions (`Profile`, `SignupArgs`, `MockBackendError`, etc.). `supabaseBackend.ts` imports those types. `backend.ts` re-exports the union. App code imports `backend` from `./backend.ts`. **Tests import `mockBackend` directly** — `vite.config.ts` has a `test.env` block forcing `VITE_SUPABASE_*=''` so the selector always picks mock during test runs regardless of `.env.local`.

### Auth model (NOT standard Supabase Auth)

PIN-based custom auth: 4 emoji icons → SHA-256(joined + salt) → stored. Three RPCs: `rpc_signup`, `rpc_login`, `rpc_recover_pin`. Lockout ladder: 5/8/10 failed attempts → 1m/5m/24h. Username profanity check happens server-side and client-side (defense in depth). Tokens are opaque + unverified — `profile_id` is passed explicitly to subsequent calls; **RLS is permissive (`anon_all` on every table)** because the gate is at the RPC layer, not in policies. Tightening this is in the backlog.

### Question pools

Math is procedurally generated by `src/generators/math.ts`. Static modules (vehicles, grammar, animals, science) live in `data/*.json` — 250 entries each, schema:
```json
{ "module_id": "...", "age_band": "5-6"|"7-9"|"both", "external_id": "...",
  "question_text": "...", "options": [...4...], "correct_index": 0..3,
  "explanation": "...", "source": "..." }
```

External IDs encode origin: `vehicles_v1_001`, `math:5-6:<hash>`, etc. Math questions are NOT reconstructable from their external_id (procedural seed isn't preserved), so `fetchIncorrectQuestions` skips math IDs by design.

`questionService.fetchQuizQuestions` filters static pools by band + dedups against `backend.getAnsweredExternalIds(profileId, moduleIds)`. The `moduleIds` arg matters for the Supabase backend (which prefix-filters `external_id`); mock ignores it.

## State stores (Zustand)

```
src/stores/
├── profileStore.ts        — current profile + token, login/logout
├── quizSessionStore.ts    — active quiz: questions, answers, score, isReviewSession, reviewQuestions
└── settingsStore.ts       — sound/volume/reducedMotion/largeText/dyslexiaFont/ageBand
```

`ageBand` in `settingsStore` is intentionally NOT persisted (`partialize` excludes it). On dashboard mount, a `useLayoutEffect` calls `initFromProfile(profile.age_band)` to sync — must be `useLayoutEffect` not `useEffect` so it flushes before the compute-progress effect fires (otherwise a one-render race shows the wrong tile set).

The Settings drawer dropdown can override `ageBand` after mount — that's intentional (parents may let a 5-6 kid try 7-9 questions).

## Quiz flow variants

```
Standard:    /quiz/:moduleId       → QuizScreen        → /results
In-session:  /quiz/review          → ReviewQuizScreen  → /review-results   (only the wrong answers from JUST FINISHED quiz)
Global:      /quiz/practice        → PracticeMistakesScreen → /practice-results  (every question ever answered wrong)
Timed:       /quiz/time-attack     → TimeAttackQuizScreen → /results       (15s per question, random module)
```

`PracticeMistakesScreen` does NOT call `recordQuiz` (would pollute `module_progress`); it only calls `logAnswered` per-question so corrections drop out of the pool next time. `ReviewQuizScreen` is similar but its source is the prior session's wrong answers, not the global pool.

## Theme + audio

`src/theme/moduleTheme.ts` — `ModuleId` union (5 modules), `MODULE_THEMES` Tailwind tokens, `themeFor(id)` with `DEFAULT_THEME` (purple) fallback for `'random'`/`'review'`/`'practice'`.

`src/services/audio.ts` — Howler wrapper. `STINGER_MODULES = Set<ModuleId>` lookup gates per-module stingers. 5 UI sounds + 5 module stingers in `public/sounds/`. All sourced under no-attribution licenses (Pixabay + Mixkit) — see `public/sounds/CREDITS.md`. Stingers play on **correct** answers only, including in review/practice/time-attack flows.

## Dashboard

`ThemedDashboard` has three view modes:
- `pick` (everything at zero) — module strip + SpecialModes
- `hero` (some progress) — ContinueHero for the lowest-progress module + module strip + SpecialModes
- `mastered` (all 100%) — celebratory ContinueHero only

`SpecialModes` row has 3 buttons: Surprise Mix (always), Practice Mistakes (only when `incorrectCount > 0` — count fetched async via `countIncorrect(profileId)`), Time Attack (always). 5-6 profiles also see a discoverability hint pointing to the age-band setting.

`MASTERY_SNAPSHOT_KEY` in sessionStorage tracks per-module mastery to avoid re-firing confetti on every re-render. `onResetProgress` clears it explicitly so confetti can fire again after a reset.

## Settings actions of note

"Reset my progress" calls `backend.resetProgress(profile.id)` — per-profile delete, NOT the wholesale `backend.reset()` (which wipes everything). Both backends implement both methods; UI uses `resetProgress`. Adult gate (`9 × 7 = ?`) gates the destructive action.

## Routes

`src/routes.tsx` (NOT `App.tsx`). Static segments must come before `:moduleId` — `/quiz/review`, `/quiz/practice`, `/quiz/time-attack` are listed before `/quiz/:moduleId`.

## Supabase setup

Migration at `supabase/migrations/0001_initial_schema.sql`. Apply via Studio → SQL Editor → paste + Run. `.env.local` (gitignored) holds:
```
VITE_SUPABASE_URL=https://<ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon-public-jwt>
```
RPC errors arrive as Postgres exceptions with bracketed prefix codes: `[INVALID]`, `[TAKEN]`, `[WRONG_CREDENTIALS]`, `[WRONG_RECOVERY]`, `[LOCKED <iso-ts>]`, `[PROFANITY]`. Client adapter pattern-matches case-insensitively.

## Conventions agents have learned the hard way

- **Don't add new comments** when changing existing code; preserve existing comments verbatim.
- **Don't revert user edits** — if a file is modified mid-task, leave it as-is even if it surfaces a TS/lint error.
- **Use theme tokens** from `MODULE_THEMES` / Tailwind palette over hardcoded colors.
- **LSP diagnostics can be stale** on fresh files; verify with `npx tsc --noEmit` before "fixing" cannot-find-module errors.
- **Don't reach for `mockBackend.reset()` in app code** — that's a wholesale wipe. Use `resetProgress(profileId)`.

## Scripts that are NOT in package.json

- Pushing requires the user's manual cmd.exe step (Codespace auth mismatch with the GitHub repo owner). Do not attempt `git push`.
- `/review` for code review is multi-agent on AWS Bedrock and runs out-of-process; needs `aws sso login` + region setup, otherwise falls back to local agents (substantial session context cost).
